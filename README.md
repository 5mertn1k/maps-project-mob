# Приложение с картой и локальной базой данных (React Native + Expo)

Мобильное приложение: маркеры на карте и изображения, привязанные к ним.
Данные хранятся в локальной базе SQLite и сохраняются между запусками.

## Установка и запуск

1. Установите Node.js (LTS) и приложение Expo Go на телефон.
2. Склонируйте репозиторий и установите зависимости:

```bash
git clone <ссылка-на-репозиторий>
cd <папка-проекта>
npm install
```

3. Запустите проект:

```bash
npx expo start
```

4. Отсканируйте QR-код в Expo Go (телефон и компьютер в одной сети).
   Если подключение не удаётся, используйте `npx expo start --tunnel`.

Проект использует Expo SDK 52.

## Возможности

- Карта на весь экран, маркер добавляется долгим нажатием
- Нажатие на маркер открывает экран деталей
- Добавление изображений из галереи, удаление изображений
- Удаление маркера вместе со всеми его изображениями
- Данные сохраняются в SQLite и остаются после перезапуска приложения

## Структура проекта

```
app/
  _layout.tsx          корневой layout, подключает DatabaseProvider
  index.tsx            экран карты
  marker/[id].tsx      экран деталей маркера

database/

  operations.ts        SQL-запросы (слой доступа к данным)

```

## База данных

Используется `expo-sqlite`, файл базы `markers.db`. Версия схемы хранится в
`PRAGMA user_version`.

### Таблица `markers`

| Колонка | Тип | Описание |
|---|---|---|
| id | INTEGER, PRIMARY KEY AUTOINCREMENT | идентификатор маркера |
| latitude | REAL, NOT NULL | широта |
| longitude | REAL, NOT NULL | долгота |
| created_at | DATETIME, DEFAULT CURRENT_TIMESTAMP | время создания |

### Таблица `marker_images`

| Колонка | Тип | Описание |
|---|---|---|
| id | INTEGER, PRIMARY KEY AUTOINCREMENT | идентификатор изображения |
| marker_id | INTEGER, NOT NULL | маркер, которому принадлежит изображение |
| uri | TEXT, NOT NULL | адрес файла изображения |
| created_at | DATETIME, DEFAULT CURRENT_TIMESTAMP | время добавления |

Связь: один маркер, много изображений. `marker_id` является внешним ключом на
`markers(id)` с `ON DELETE CASCADE`, поэтому при удалении маркера его изображения
удаляются автоматически. Внешние ключи в SQLite по умолчанию выключены, поэтому при
каждом открытии базы выполняется `PRAGMA foreign_keys = ON`.

### Миграции

При запуске читается `PRAGMA user_version`. Если версия базы меньше актуальной,
выполняются недостающие миграции внутри одной транзакции, после чего записывается
новая версия. Если миграция упала, транзакция откатывается и база остаётся в
предыдущем согласованном состоянии. Чтобы изменить схему, нужно увеличить
`LATEST_VERSION` и добавить блок `if (currentVersion < N)` в `database/schema.ts`.

## Архитектура

- **Слой данных** (`database/operations.ts`): чистые функции с SQL-запросами, принимают
  подключение первым аргументом, не зависят от React. Все значения передаются через
  параметры `?`, а не конкатенацией строк, что исключает SQL-инъекции.
- **Контекст** (`contexts/DatabaseContext.tsx`): открывает базу, применяет миграции,
  раздаёт экранам CRUD-операции, статусы `isLoading` и `error`.
- **UI** (экраны и компоненты) работает только с функциями контекста и не содержит SQL.
- Источник правды для данных это база. После каждого изменения экраны перечитывают
  данные из базы, поэтому интерфейс всегда соответствует сохранённому.

## Обработка ошибок

- **Инициализация базы.** Ошибки открытия файла и миграций перехватываются в
  `DatabaseProvider`. Пока база готовится, показывается индикатор загрузки, при сбое
  экран с текстом ошибки и кнопкой «Повторить». Кнопка увеличивает счётчик попыток,
  который указан в зависимостях `useEffect`, и инициализация запускается заново без
  перезапуска приложения.
- **Операции с базой.** Все операции проходят через обёртку `run`: она проверяет, что
  база открыта, логирует вызов (только в режиме разработки, `__DEV__`) и превращает
  любую ошибку (нарушение ограничений, сбой транзакции) в сообщение вида
  «Ошибка базы данных (операция): причина».
- **Экраны.** Вызовы базы обёрнуты в `try/catch`, сообщение показывается в `Alert`.
- **Транзакции.** Миграции и удаление маркера выполняются в транзакциях.
- **Очистка ресурсов.** При размонтировании провайдера соединение закрывается,
  флаг `cancelled` защищает от обновления состояния после уничтожения компонента.
- **Выбор изображений.** Обрабатываются отказ в доступе к галерее, отмена выбора и
  ошибки `expo-image-picker`.
- **Навигация.** Возврат к карте обёрнут в `try/catch` с запасным переходом на `/`.
- **Карта.** Если не загрузилась библиотека карты или плитки, показывается сообщение
  и кнопка «Повторить».

## Принятые решения

- **Карта:** вместо `react-native-maps` использована связка `react-native-webview` +
  Leaflet + плитки OpenStreetMap. Нативная карта в Expo Go на тестовом устройстве
  отображалась пустой, поэтому выбрана альтернатива на OpenStreetMap, рекомендованная
  преподавателем. Обмен данными между картой и приложением идёт через `postMessage`
  (страница шлёт события нажатий, приложение передаёт список маркеров).
- **Навигация:** Expo Router. Экран деталей получает `id` из адреса `/marker/[id]`
  (в адресе это строка, на экране преобразуется в число).
- **ORM не используется:** схема из двух таблиц небольшая, поэтому выбраны
  параметризованные SQL-запросы через `expo-sqlite`.
- **Обновление карты:** на экране карты используется `useFocusEffect`, чтобы
  перечитывать маркеры при возврате с экрана деталей (экран карты остаётся
  смонтированным под ним).

## Дополнительные функции

- Версионирование базы через `PRAGMA user_version` и транзакционные миграции
- Удаление маркера из интерфейса (с каскадным удалением изображений)
- Предпросмотр изображения на весь экран
- Подтверждение перед удалением изображений и маркеров
- Экран «Маркер не найден»
- Логирование операций с базой в режиме разработки

## Известные проблемы и ограничения

- Для карты нужен интернет (Leaflet и плитки загружаются из сети).
- В базе хранится только адрес изображения. Файл остаётся во временной папке
  приложения, которую система может очистить, тогда изображение перестанет
  отображаться. Надёжное решение: копировать файлы в постоянную директорию
  через `expo-file-system`.
- Удаление изображения убирает запись из базы, но не удаляет файл из кэша.
- Приложение проверялось только на Android через Expo Go.
